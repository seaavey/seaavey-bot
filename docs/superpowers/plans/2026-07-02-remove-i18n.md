# Remove i18n System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the multi-language (i18n) translation system from SeaaveyBot and inline natural, human-written English text directly into all code files.

**Architecture:** A TypeScript migration script will automate the inlining of translation strings across over 200 files. We will translate any remaining Indonesian strings to natural English, map template parameters to TypeScript template literals, and remove the translation modules.

**Tech Stack:** Bun, TypeScript, Node.js filesystem APIs.

## Global Constraints
- Runtime: Bun (always use `bun` instead of `npm`/`node`).
- Strict TypeScript: Ensure strict mode and type safety are maintained.
- Code Style: Follow ESLint rules, format code with Prettier, and run linting/tests.
- Emojis: Can be used in messages but selectively and not too frequently.

### Task 2: Build the Migration Script

**Files:**
- Create: `scratch/migrate.ts` (in the artifact scratch directory)

**Interfaces:**
- Consumes: `scratch/translations_map.json`
- Produces: Inline modifications in all `src/**/*.ts` files

- [ ] **Step 1: Write the migration script**
  Create `/home/seaavey/.gemini/antigravity-cli/brain/d13342d1-43d3-4012-a26b-9e14b3717083/scratch/migrate.ts` to replace `t(...)` calls.
  The script will:
  1. Load `translations_map.json`.
  2. Search all TS files under `src/`.
  3. Locate calls like `t("key")` or `t("key", { param: val })`.
  4. Replace them:
     - If no params, replace `t("key")` with `"natural text"` (properly escaped).
     - If params, parse the params object and construct a template string. For example, `t("group.warn.warned", { target: getNumber(target), count: warns.length, max, reason })` becomes `` `⚠️ @${getNumber(target)} warned! (${warns.length}/${max})\nReason: ${reason}` ``.
  5. Remove the `import { t } from "@/core/translations";` line.
  6. Write modified files back.

- [ ] **Step 2: Run verification on the migration script**
  Test the migration script logic on a dummy file or double-check its regexp replacements before execution.
